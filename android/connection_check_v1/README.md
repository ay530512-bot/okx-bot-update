# 1.2.3 연결 비교 진단 — 2026-11-15 KST

설치 업데이트나 연결 장애 수정본이 아니다. 실시간 원인 비교를 위한 별도 프로세스다.
phone_latest.json, 실행 중인 봇, 주문, 계좌, 설정, 재시작 명령을 변경하지 않는다.
공개 AAVE-USDT-SWAP ticker 소켓 두 개를 추가한다. 기존 289종목 수신량과 비교해 작은
부하이나 네트워크/CPU 부하가 0은 아니다.

- idle: 20초 수신 중단 시 text ping.
- periodic: 수신 여부와 무관하게 20초 간격 text ping.
- 공통: 같은 IPv4/TLS와 해시로 검증한 1.2.3 수신 어댑터, 수신 45초 중단 시 재연결,
  실패 시 2~30초 대기. 1초 간격으로 시작한다. API 키를 읽지 않는다.
- 기존 phone_connection_trace.json은 2초 간격으로 허용 필드만 읽는다.
- 600초 후 종료한다. DNS 등에서 멈춘 worker는 daemon이며 결과에 worker_pending으로 표시한다.
- 중복 실행은 파일 잠금으로 차단한다. SSH 세션과 분리되지만 Android가 Termux를
  종료하거나 재부팅하면 중단될 수 있다. Android 배터리 설정은 변경하지 않는다.

`python -B check.py` 실행. 10분 후 `~/okx-phone/connection-check/result.txt` 확인.
원시 증거는 같은 디렉터리 events.jsonl/result.json. 다시 실행하면 이전 결과를 덮어쓴다.
도구가 자동으로 결과를 외부에 전송하지 않으며 이 대화에서 폰의 결과를 직접 읽을 수 없다.

해석: 독립 연결 동시 종료는 공통 네트워크/서버 요인의 조사 근거이나 원인 확정이 아니다.
봇만 종료돼도 구독량과 서버 경로가 다르므로 봇 결함을 확정하지 않는다. periodic만
살아남아도 한 번의 10분 결과로 ping 정책을 실거래 프로그램에 채택하지 않는다.
무단절 10분은 장기 안정성 증명이 아니다. 시세 미수신/기록 노후/봇 재시작은 비교 한계다.

검사: 5개 로컬 테스트(heartbeat 조건, 오래된 기록/카운터 초기화,
민감 필드 배제, 두 연결 시세 수신, 실제 종료 예외 기록) 통과.
네트워크/소켓은 모의 객체이며 사용자 폰/실제 OKX 장시간 연결 검증 결과가 아니다.

공식 기준: https://www.okx.com/docs-v5/en/#overview-websocket
문서는 수신 중단 시 ping을 권고한다. periodic 정책은 원인 비교용 실험이며
ping 0회 자체를 오류로 간주하지 않는다.
