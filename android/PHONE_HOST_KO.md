# 폴드3 실행기 · Q2X

계정 조회 단계 다음에 사용하는 Android 실행기입니다. Q2X 원본 엔진 148개 파일과 사용자가 확인한 전략 설정을 변경하지 않습니다. PC용 ZIP이나 AI_FREE_5X 폴더에 덮어쓰는 업데이트가 아닙니다.

## 현재 확인 범위

실기기에서 공개 API, 짧은 공개 WebSocket 수신, 로컬 브라우저의 계정 조회가 확인되었습니다. 이번 실행기의 거래 활성화·체결·보호주문·재시작 복구·화면 꺼짐 장시간 운용은 실제 폴드3에서 아직 확인하지 않았습니다. 아래 설치는 기본적으로 **조회 모드**입니다.

## 1. 실행기 설치 및 조회 화면

Termux에서 기존 조회 화면을 Ctrl+C로 종료합니다. PC 매매에는 영향이 없습니다. GitHub의 `android/phone_host_setup.py`를 내려받아 `python`으로 실행합니다. 제공된 명령에는 게시한 커밋이 고정되어 있습니다.

설치 파일은 `~/okx-phone/host-v1`에 저장됩니다. 기존 API 정보와 전략 설정을 다시 입력하지 않습니다. 최초 한 번 폰 대시보드에 사용할 비밀번호(8자 이상)를 두 번 입력합니다. 암호 입력 중 글자가 안 보이는 것은 정상입니다.

폰 Chrome에서 **http://127.0.0.1:8768** 접속 → 비밀번호 입력. 조회 상태에서는 모든 주문 제어가 차단됩니다. 아직 보유분이 있으면 PC가 계속 관리해야 합니다.

다시 조회 모드로 열기:

```sh
python -B ~/okx-phone/host-v1/phone_host.py
```

`8767`은 이전 계정 설정 화면, `8768`은 이번 폰 대시보드입니다. 이 주소는 폴드3 자체에서만 접속됩니다. 기존 iPhone의 PC/Tailscale 주소가 자동으로 폴드3로 바뀌지는 않습니다.

## 2. Telegram 알림 설정 (원하는 경우, 최초 전환 전)

이전 계정 연결 단계에서는 OKX API 세 항목만 저장했습니다. PC의 Telegram Bot Token과 Chat ID는 자동으로 옮겨지지 않습니다. 필요한 경우 조회 실행기를 Ctrl+C로 끝낸 뒤:

```sh
python -B ~/okx-phone/host-v1/phone_host.py --telegram
```

해당 값은 폰 Termux 입력창에서만 입력하세요. 채팅이나 GitHub에 올리지 마세요. 저장만 하며 테스트 메시지는 자동 발송하지 않습니다. 미설정 상태에서는 폰 거래 알림이 전송되지 않습니다. 운용 시작 후에는 기존 알림 기록과의 대조 없이 수신 대상을 바꾸지 않습니다.

## 3. PC에서 폰으로 최초 전환

1. PC 또는 기존 PC 모바일 화면에서 **신규 진입 중지**를 누릅니다. 이는 기존 보유분의 관리 중지가 아닙니다.
2. 보유 포지션·미체결·조건주문이 모두 **0**이 될 때까지 PC를 유지합니다. 이 설치기는 전환을 위해 자동 청산하거나 SL을 취소하지 않습니다. 잔여 조건주문이 있으면 연결된 보유분/주문부터 확인하세요.
3. 모두 0일 때 PC 프로그램을 정상 종료합니다. 자동 실행도 꺼 둡니다. PC를 원격으로 확인하거나 종료하는 기능은 없습니다.
4. 폰 Termux에서 조회 실행기를 Ctrl+C로 끝내고 다음을 실행합니다.

```sh
termux-wake-lock
python -B ~/okx-phone/host-v1/phone_host.py --takeover
```

5. 요청 시 `PC 종료 완료`를 입력합니다. 계정/주문을 두 번 새로 조회하고 하나라도 남아 있으면 전환을 거부합니다. 확인 오류가 나면 기록 파일을 삭제하거나 강제로 우회하지 마세요.
6. Chrome의 **http://127.0.0.1:8768**을 새로고침합니다. 홈의 **실거래 시작 → 확인 · 자동매매 활성화**로 현재 잔고와 규칙을 확인한 뒤 시작합니다. 이 확인 이후 실제 주문이 발생할 수 있습니다.

폰이 실행을 담당하는 동안 PC 프로그램을 다시 켜면 안 됩니다. 최초 전환 시 폰 엔진은 정지 상태로 시작하며, 기존 PC의 포지션/주문 기록은 가져오지 않습니다. 첫 실제 운용에서는 계정 연결, 신규 진입 체결, 거래소 SL 등록과 이후 보호 갱신을 관찰해야 합니다. 코드 검사는 실기기 성공을 대신하지 않습니다.

## 4. 이후 실행 및 종료

이미 폰으로 전환한 뒤 다시 실행할 때:

```sh
termux-wake-lock
python -B ~/okx-phone/host-v1/phone_host.py --run
```

기존 폰 기록을 유지하고 계정이 같은지 확인합니다. Q2X 원래 복구 규칙에 따라 **비정상 종료 전 가동 상태라면 계정/미체결/SL 대조 후 자동 재개할 수 있습니다.** 직접 신규 진입 중지나 정상 종료를 했다면 화면에서 다시 시작해야 합니다. `--takeover`를 반복하거나 `bot_state.json`을 삭제하지 마세요.

Ctrl+C는 신규 진입 중지와 정상 종료를 요청합니다. 폰 관리 보유분이 있으면 Q2X가 종료를 거부하고 관리를 계속합니다. 보유분이 없어진 후 Ctrl+C를 다시 누릅니다. Android의 강제 종료, 전원 단절까지 막는 기능은 아닙니다.

아직 제공하지 않는 기능: iPhone에서 폰으로의 외부 접속, 재부팅 후 자동 기동, 폰 전용 자동 업데이트. PC용 업데이트는 폰 화면과 제어 경로에서 차단합니다. Windows/Tk 실행기를 폰에 설치하지 않습니다.

## 개발 검증

`phone_host.py`는 실행 위치/화면/최초 전환만 연결합니다. 진입, 청산, 주문 크기, 수수료 계산, 보호 SL, 15분 긴꼬리 청산 코드는 Q2X 원본을 사용합니다. 화면 모듈에서만 Tk의 등락률 분류 함수를 순수 Python으로 분리하고, 접속을 loopback에 한정하며, 같은 출처의 인증된 제어 요청을 기존 직렬 명령 큐에 전달합니다.

회귀 검사에 원본 코드를 지정하려면 `OKX_PHONE_TEST_SOURCE` 환경 변수에 SHA 검증한 Q2X 폴더를, 실제 설정 호환성 검사에는 `OKX_PHONE_TEST_CONFIG`에 로컬 전략 JSON 경로를 지정합니다. 개인 설정은 저장소에 넣지 않습니다.

```sh
python -m unittest discover -s android -v
```

데이터/개인 키가 없는 모의 검사입니다. 검증 세부 범위는 `host_validation.json`에 기록합니다.
