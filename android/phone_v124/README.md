# 1.2.4 연결 유지 방식 복원 후보 — 2026-11-15 KST

사용자는 업데이트 이전에 폰 자동 주문이 실제 성공했다고 보고했다. 마지막 성공 버전/주문
기록을 독립 확인하지 못했으므로 1.1.6을 '사용자에게 검증된 정상 버전'이라고 명명하지 않는다.

보관된 설치기 PAYLOAD를 실행하지 않고 해시 확인 후 해제해 비교했다.

| 파일 기준 | 확인한 동작 |
|---|---|
| 1.1.2~1.1.6 public-ws-1 | 시세 수신 여부와 무관하게 20초 text ping, pong 지연만으로 강제 종료하지 않음 |
| 1.1.7~1.1.8 public-ws-2 | 20초 text ping + pending pong 20초 초과 시 종료; 수신 중에도 오탐 가능 |

| 1.2.4 public-ws-4 | 정기 20초 ping 복원; 수신이 계속되면 pong 지연만으로 종료하지 않음; 진짜 무응답 복구 유지 |

1.1.3/1.1.6/1.1.7/1.1.8과 현재의 core archive hash는 동일:
`6b2a0a90f02cca914ffc5cc0996555e8c1435b7a61618575ee94ee2ebdc2dad1`.
core가 같아도 런타임 래퍼와 사용자 설정이 같다는 의미는 아니다.

1.2.4는 전략/신호/후보/계좌/주문량/인계 모듈을 1.2.3과 바이트 단위로 보존한다.
핵심 변경은 ping 송신 조건뿐이며, 마지막 종료 원인의 한국어 화면 표시를 추가한다.
최신 시세·신호 만료·최종 주문 검사·세대 확인·TLS 검증·보호 주문 인계는 유지한다.

## 증거와 한계

- 사용자 폰: 18:02:03 EOF → 18:02:06 연결 → 18:02:15 진입 차단 해제 관측.
- 이전 연결 수명 3628.312초; 더 이른 EOF는 254.369초. 일정 주기 종료로 단정 불가.
- 앞선 600초 비교에서 bot/idle/periodic 모두 무단절. 정기 ping의 개선 효과를 입증한 결과가 아니다.
- 따라서 이번 변경은 과거 연결 유지 방식의 좁은 복원 후보이며 EOF 원인 해결 완료가 아니다.
- 로컬: 통신 27개 + 기존 안전 인계/업데이트 거래 처리 22개 = Python 49개 통과.
- UI DOM 상태 3개 검사(EOF 원인 문구 포함), 설치기 해시 확인/중복 staging 검증.
- 실시간 OKX/사용자 폰 장기 무단절 또는 실제 체결 검증 없음. 거래를 강제하지 않는다.

1.2.3 host-v21 파일 해시가 일치할 때만 host-v22를 준비하고 기존 안전 인계를 수행한다.
설치 과정에 보유/보호 상태가 불확실하면 보류한다. 구버전 전체 덮어쓰기/강제 청산 없음.
