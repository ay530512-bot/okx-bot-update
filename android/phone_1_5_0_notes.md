# OKX Ai trade 1.5.0

1.4.2의 자료 수집·진단 보존 수정을 포함한 누적 업데이트입니다. 1.4.2를 먼저 설치할 필요 없이, 기존 폰의 **활동·설정 → 폰 새 버전 확인 → 1.5.0 설치**로 진행합니다. 설치가 끝나면 화면을 새로고침해 1.5.0을 확인합니다. 휴대폰에 실제로 설치된 것은 사용자가 설치 버튼을 누른 뒤입니다.

## 추세 전용 자리의 표시

같은 영역에 다음 내용을 함께 표시합니다.

- **현재 시세 상승률 1위:** 시세 화면과 같은 KST09시 시가 대비 현재가 기준의 종목·등락률·확인 시각.
- **규칙의 실제 검사 대상:** 기존 순위 계산인 KST09시 시가 대비 최근 완료 1시간봉 종가 기준. 오전 05~08시에는 오전 숏 대상, 그 외에는 기존 추세 롱 대상을 표시.
- **현재 단계:** 새 돌파 대기, 눌림 종가 대기, 반등 실패 대기, 필수 자료 대기를 구분.
- **누락 자료:** 종목과 구체적인 이유, 보관 중인 1시간봉 개수. 진단 자료나 시세가 오래되면 현재 확인된 값처럼 표시하지 않음.

스크린샷의 `순위 자료 대기: JCT-USDT-SWAP`는 **JCT가 상승률 1위라는 뜻이 아니라, 전체 순위를 확정하는 데 필요한 JCT의 완료 1시간봉 자료가 부족하거나 유효하지 않다는 뜻**입니다. `285/286` 상태라면 전체 순위 확정은 아직 대기 중입니다. 이 상태를 “1위 눌림을 정상 감시 중”이라고 단정할 수는 없습니다.

기존 표시는 누락 종목만 보여 주어 이를 검사 대상으로 오해하기 쉬웠습니다. 이번에는 현재 시세 1위를 별도로 보여 주고 대기 문구를 분명히 바꿉니다. 두 순위는 현재가와 완료봉 종가를 사용하므로 다를 수 있습니다. **기존 순위 계산을 바꾸거나 CASHCAT을 고정 대상으로 지정하지 않았습니다.** 당시 JCT의 원본 봉 기록은 제공되지 않아, 그 시점의 누락 원인이 미수신·최신 봉 지연·기준봉 부족 중 무엇이었는지는 확정하지 않습니다. 업데이트 후에는 해당 원인이 화면과 저장 진단에 남습니다.

## 기존 롱 유지 + 오전 숏 추가

| 구분 | 동작 |
| --- | --- |
| 기존 추세 롱 | 진입 조건·수량·5배·KST15:00~다음02:00·기존 추적 관리 유지 |
| 오전 숏 신규 진입 | **KST05:00 이상, 08:00 미만**에만 허용. 08시 이후에는 새 진입과 새 전환 금지 |
| 대상 | 기존과 같은 전체 허용 종목의 완료 1시간봉 상승률 1위. 필수 자료가 빠지면 부분 순위로 주문하지 않음 |
| 큰 눌림의 수치화 | 완료 15분봉 기준, 최근 6시간의 직전 고점에서 **2% 이상이면서 1.5ATR 이상** 하락 |
| 반등 실패 | 눌림 저점에서 **0.5ATR 이상** 반등하고 양봉이 나온 뒤, 직전 고점을 넘지 못함 |
| 재하락 확인 | 음봉이 직전 봉 저가 아래로 마감하고 그 봉의 고가도 반등 고가보다 낮음 |
| 주문 | 5배 숏, 기존 전용 자리와 같은 시드 1/4 한도. 완료봉 신호 유효시간 90초, 재진입 중복 금지, 기존 계좌·호가·스프레드·주문 검사 유지 |
| 초기 손절 | 반등 고가 + 0.2 × 15분 ATR |
| 추적손절 | 실제 관측한 진입 이후 최저 가격 + 2 × 15분 ATR. 손절선을 불리하게 넓히지 않음. 전량 추적, 별도 절반 익절 없음 |
| 보유 관리 | 08시가 지나도 손절·추적 관리 계속. 최대 72시간 |

위 2%·ATR 수치는 “큰 눌림 → 반등 실패 → 재하락”을 실행 가능한 조건으로 구체화한 이번 기본값입니다. 수익성이 검증된 최적값이라는 뜻은 아닙니다.

## 롱에서 숏으로 전환

기존 추세 전용 롱을 보유한 상태에서 오전 숏 조건이 확인되면 다음 순서로 처리합니다.

1. 운용 허용 상태, 전환 대상의 실시간 시세와 신호를 검사합니다.
2. 추세 전용 롱에 청산을 요청하고 요청 정보를 저장합니다.
3. 거래소의 **전량 청산 체결·롱 잔량 0·미체결 및 기존 보호주문 정리**를 확인합니다.
4. 새 계좌·시장 자료로 시간·순위·90초 신호 유효성 및 기존 진입 검사를 다시 통과하면 숏에 진입하고 보호주문을 확인합니다.

청산 요청만으로 숏을 먼저 열지 않습니다. 부분 체결이나 응답 미확인 상태에서 중복 청산/반대 포지션을 생성하지 않습니다. 청산 후 08시가 되거나 신호가 만료되거나 최종 검사를 통과하지 못하면 숏을 강제로 열지 않습니다. 전용 자리가 찬 경우에도 오전 전환을 위한 자료 수집은 계속합니다. 일반·수동 포지션은 전환 대상으로 삼지 않으며, **일반 3자리 + 전용 1자리, 전체 최대 4포지션**을 유지합니다.

## 설치와 검증 범위

지원 범위는 기존 내부 배포번호 24~39 → 40입니다. 별도 실행기 폴더로 설치하고 기존의 보유·보호 인계, 설정 유지, 이전 버전 복원 절차를 사용합니다. 교체 중 로컬 추적 관리는 잠시 쉬지만 거래소에 이미 등록된 보호주문은 유지됩니다. 업데이트 버튼 자체가 실거래 시작을 대신하지 않으며 기존 운용/중지 상태를 인계합니다.

검증 결과와 설치 파일 해시는 `phone_v150_tests/validation.json`에 있습니다. 실제 전략 함수·주문 엔진을 가짜 거래소에 연결해 주문 제출, 체결 확인, 보호주문, 4자리 제한, 부분 청산, 응답 미확인, 재시작, 08시 경계 및 중복 금지를 검사했습니다. 화면 검사는 최소 DOM 환경에서 현재 1위와 실제 대상, 자료 대기, 오전 숏 표시를 확인합니다.

기존 7개 방향별 진입 사례는 이전 검증의 역사적 봉 자료를 재사용했고, 오전 숏 사례는 합성 봉 자료를 사용했습니다. 호가·계좌·계약 정보와 체결은 모의 값입니다. **실제 휴대폰 설치·실제 거래소 체결·수익성 백테스트를 완료했다는 의미는 아닙니다.**

오프라인 재검증(Python 3.12, Node.js, python-dotenv, websocket-client 필요):

```bash
python android/phone_v150_tests/run_validation.py
```

이 명령은 저장소 안의 고정 원본 자료로 테스트용 소스를 복원하며, 실거래 서비스를 실행하거나 실제 주문을 전송하지 않습니다. 테스트용 복원 폴더는 저장소의 상위 폴더에 생성되므로 별도 체크아웃에서 실행하는 것을 권장합니다.
