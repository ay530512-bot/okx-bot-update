# 1.3.1 — 1.3.0 유지 및 진입 거절 진단 수정

## 확인 결과

사용자가 보낸 최신 기록은 실행 361.467초의 새 세션이다. 시세·계좌 연결 및 계좌 신선도는 정상, 복구 대기/사용자 중지/진입 취소는 false, 진입 허용은 true다. 당시 준비 신호는 0개였고, 출력된 주문 단계 계측은 없었다. 이 기록으로 이전 270분 전체의 진입 누락 여부를 판정할 수 없다.

원본 코드에서 1시간봉 부족 또는 불연속도 패턴 결과 None으로 반환될 수 있고, 폰 화면이 이를 모두 '패턴 조건 미충족'으로 집계하는 표시 문제를 재현했다. 사용자의 실제 기기에서 1시간봉 부족이 발생했다는 증거는 아직 없다.

현재 기본 전략은 mild726의 상태 선택(1시간 추세효율 0.30 이상이면 눌림목, 미만이면 확정반전) OR two_wick732다. 즉 눌림목·확정반전이 언제나 동시에 독립적으로 활성화되는 구조가 아니다. 두꼬리에도 시간봉 추세·효율·MA50·거래량 확인이 있다. 과거 '독립된 3규칙'이라는 설명은 이 상태 선택을 누락했다. 이번 버전은 기준을 바꾸지 않고 실제 구조를 표시한다.

## PC 원본과 폰 비교

이식 당시 보존한 Q2X PC 원본의 파일 해시를 검증했다. 그 원본과 폰1.2.9/1.3.1의 단일·실제4프로세스 계산을 같은 OHLCV로 비교했다.

- 자료: 기존 보관 Binance ARB/OP/SEI/WLD/TIA, 2026년8~10월. 전부 재사용 자료.
- 표본: 기존 알려진 기본/두꼬리 신호 시점 + 일정 간격 대기 시점, 총362개 종목-시점.
- 신호: 눌림목34, 확정반전30, 두꼬리6, 합계70. 나머지292는 대기.
- 진입 증거값과 OR 상태가 모두 일치했다. 확률/수익성 검사가 아니라 구현 일치 검사다.
- 사용자가 이틀 전에 실제로 실행했던 PC 파일·같은 시각 원시 봉·로그는 확보되지 않았다. 당시 기회와 지금 기회를 동일 조건으로 비교한 것은 아니다.
- 실기기 수신 지연, 주문 호가, 유효시간90초, 계약단위/배율, 가용금/보호주문 검사 때문에 실제 체결은 달라질 수 있다. 이들은 이번 과거 신호 비교에서 모두 재현된 것이 아니다.

## 수정한 진단

1. 각 경로의 통과/조건대기/자료대기/상태별 비활성을 분리한다.
2. 자료 부족을 단순 패턴 탈락으로만 표시하지 않는다.
3. 두꼬리의 최초 탈락 단계를 구분한다: 꼬리 형태, 시간봉, 추세/효율/MA방향, 거리/거래량.
4. 검사 관측 횟수·주문 전 검사로 전달한 횟수·거절 이유의 실행 중 누적을 기록한다. 반복 검사가 포함되므로 거래수나 고유신호수로 해석하지 않는다.
5. 기존 성능 기록 스레드에서 분당 최대1회의 관측을 `phone_entry_history.jsonl`에 추가한다. 재시작 때 지우지 않는다. 파일2MiB 초과 시 이전 파일1개를 유지하므로 보존량은 대략4MiB다. 모든 이벤트를 빠짐없이 기록한 체결 감사 로그는 아니다.
6. 추세 전용자리 상태도 따로 표시한다. 과거 누락 기록을 소급해서 복원하지 않는다.

진입·청산 조건, 신호90초, 보호SL, 1.3.0의 기존3자리+추세1자리, 추세5배/1/4 증거금/절반익절 없음/72시간, 기존 계산 방식 선택은 유지한다. API 조회·실주문·사용자 기기 재시작은 이 개발 검사에서 수행하지 않았다.

## 검사

- 진단/자료누락/기록보존7개 검사 통과.
- 단일/4개분산, 오래된 결과 폐기, 연결전환, 마지막 주문검사 등15개 검사 통과.
- 업데이트·5개 이전버전·3+1 자리·5배·1/4·보호SL·추세관리 등12개 검사 통과.
- 추세 과거110신호 구현일치 확인.
- 화면 문자열/상태3개 검사 통과. 실제 브라우저 렌더링 검사가 아니다.
- 원본 조건식은 변경하지 않는다. 두꼬리는 검증된 원본 AST의 반환값에 이유만 붙이고, 기존 기본규칙 분석 결과에서 같은 우선순위로 신호를 선택한다.

## 업데이트 및 다음 확인

현재1.3.0 화면의 활동·설정 → 폰 새 버전 확인 → 업데이트. 완료 후 화면과 진단의 버전이1.3.1인지 확인한다. 기존 포지션·보호주문 인계가 준비되지 않으면 기존 설치기의 보류/복원 절차를 따른다.

다음 확정15분봉 마감 이후 활동·설정의 규칙별 진단을 확인한다. 자료대기라면 수신 경로를, 조건대기라면 해당 실제 봉과 기준을, 신호통과 후 주문전달0이라면 만료·실시간호가·중복·배율 등 후속 거절을 조사한다. 이 업데이트를 진입 불가 원인 해결 완료 또는 수익성 검증 통과로 표시하지 않는다.

재현: `test_diagnostics.py`와 `test_release.py`; 1.2.9 비교는 `OKX_AUDIT_HOST=host-v27 python test_diagnostics.py`. 기존 Q2X원본·host24~29 fixture·연구봉 자료가 필요하다. 기준경로는 테스트 파일에 명시돼 있다.
