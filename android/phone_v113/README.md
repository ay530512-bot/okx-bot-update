# OKX Ai trade - 1.1.3

## 변경

- 상단 이름을 OKX Ai trade - 1.1.3으로 통일.
- 기존 32px 카드 여백 유지.
- 엔진/계정 전체 조회/일일 현금흐름/조건주문/종목 탐색/캔들 조회 또는 캐시/신호 평가/진입/SL 검증/추적/청산/빠른 보호/API 전체 호출/HTTP 통신/읽기 호출 제한 대기를 계측.
- 정상 운용 중 중간 **빈 슬롯**에서만 중복 계정 스냅샷 조회 생략. 최초 조회와 마지막 슬롯 조회, 모든 보유 슬롯 조회, 진입 직전 검사, 복구 중 검사를 유지. API 결과 캐싱이나 호출 제한 완화 없음.
- 성공한 정상 운용 첫 5회는 기존 조회 순서를 유지하여 baseline 수집. 이후 optimized 수집. 중지·복구 상태는 별도 safety_or_paused 그룹.
- 원본 전략 파일은 변경하지 않음. 핀 검증된 RuleEngine.tick의 메모리 AST에 빈 슬롯 가드 한 개만 삽입. AST 대조 검사로 그 외 진입/청산 분기 동일 확인.

## 검증과 해석

로컬 검사: 계정이 빈 4슬롯 tick의 스냅샷 호출 **5 → 2**. 실제 단말 속도 개선률은 아직 미측정. 시뮬레이션 호출 감소를 거래 수익 개선이나 실기 성능 개선률로 표현하지 않음.

inclusive(total_s)는 중첩 호출을 포함하므로 서로 더하지 말 것. self_s는 측정한 하위 호출을 제외한 벽시계 시간으로 CPU 시간은 아님. HTTP 측정은 거래소 처리·네트워크 대기를 함께 포함. background 그룹은 별도 스레드의 탐색/보호 작업이며 엔진 tick과 병렬일 수 있음. baseline과 optimized는 서로 다른 시간대이므로 부하가 같다고 가정하지 말 것. 수익성이나 PC 대비 성능 검증은 수행하지 않음.

파일 `~/okx-phone/phone_performance.json`은 전용 관측 스레드에서 5초마다 저장. 최대 metric 항목160개, 최근 tick30개. API 키/서명/요청 본문/응답 본문/종목별 주문 식별자/예외 원문은 기록하지 않음. 성능 측정 때문에 API를 새로 호출하지 않음. 화면 활동·설정 아래에서 평균 tick와 생략 횟수 확인 가능.

상세 읽기:
```
python -B ~/okx-phone/host-v11/phone_performance.py
```

## 설치

1.1.2(host-v10)에서 모바일 업데이트 버튼 사용. 신규 진입 중지·보유/주문 0의 기존 설치 제한 유지. 정상 종료 후 새 실행기 준비 확인, 실패 시 이전 버전 복원 절차. 설치 이후 실거래 시작은 사용자 확인. 실제 폴드에서 첫 5회 및 이후 관측이 쌓여야 실제 병목과 속도 변화를 판정할 수 있음.
